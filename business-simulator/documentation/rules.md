# Project Rules

## 1. File Length
No file should be longer than 150 lines of code.

## 2. Code Quality
- Write clean, modular, and reusable code.
- Follow ESLint and Prettier rules for code formatting.

## 3. Testing
- Write unit tests for all new features.
- Ensure all tests pass before submitting a pull request.

## 4. Documentation
- Maintain comprehensive comments and documentation for all code.
- Update project documentation regularly to reflect any changes or new developments.

## 5. Collaboration
- Use GitHub for code management and collaboration.
- Follow the branching strategy with `main`, `develop`, and feature branches.
